# Журнал фаз MVP

## Ф2. Текстовые обращения, виджет, рабочее место оператора — выполнена (28.09.2026)

**Сделано**

- Миграция `0003`: клиенты и их идентификаторы в каналах, каналы, обращения (статусы, очередь, оператор, тема с путём,
  предприятие/подразделение/объект, важность, срочность, поля карточки, результат), теги обращений, сообщения
  (номер в обращении, направление in/out/system/note, вложения, идентификатор в канале — защита от дублей),
  вложения, согласия на обработку ПДн.
- Пакеты: `@cc/auth` (токены, загрузка прав, области видимости — общие для api и realtime), `@cc/domain`
  (приём входящего сообщения, добавление сообщения, события обращений).
- **worker** (новый сервис): поток `CC_INBOUND` → клиент по идентификатору → открытое обращение или новое в очереди
  канала → сообщение. Подтверждение только после записи в БД; повторная доставка не создаёт дублей; сообщения
  одного клиента обрабатываются последовательно (advisory lock).
- **realtime** (новый сервис): WebSocket операторов и клиентов; события — из `CC_EVENTS`; оператору — по правам и
  области видимости, клиенту — только его диалоги и никогда внутренние заметки; «печатает…» в обе стороны;
  проверка отзыва сессии; при остановке — код 1012 и переподключение к другому экземпляру.
- **Клиентский API** (`/api/v1/client`, он же «коннектор» веб-чата): настройки виджета, сессия с согласием на
  обработку ПДн (версия текста, IP), разрешённые сайты (CORS), ограничение частоты, сообщения с идемпотентным
  `clientMessageId` (ответ клиенту — после записи в JetStream R3), вложения; чат в приложении с подписью
  пользователя приложения (HMAC).
- **Операторский API**: вкладки «Мои / Очередь / Все открытые / Закрытые», «Взять» (с лимитом одновременных чатов),
  ответы, внутренние заметки, вложения, классификация (тема → автоматически «особо важное», предприятие,
  подразделение, объект, поля темы, теги, срочность), передача оператору или в очередь, закрытие с результатом
  (тема и обязательные «при закрытии» поля проверяются), карточка клиента и кросс-канальная история. Области
  видимости применяются к обращениям (прямой доступ к чужому — 404).
- **Виджет** (`apps/widget`, Preact, 22 КБ, Shadow DOM): встраивание одним `<script>`, согласие, вложения,
  повторная отправка без дублей, переподключение с догрузкой, «печатает…»; `/widget/demo.html` и
  `/widget/mobile.html` для WebView приложения.
- **Веб**: рабочее место оператора (3 панели, realtime, уведомления звуком/в заголовке/системные), раздел «Каналы».

|---|---|

| e2e Ф2: виджет → очередь → «Взять» → ответ с файлом → ответ клиента в реальном времени → заметка (клиенту не видна) → закрытие (без темы — отказ) → повторное обращение, история видна | пройден |

| Тесты: api 22 (из них 13 интеграционных на PostgreSQL), realtime 4, auth 9 и др. | все зелёные |

**Решения и находки**

- Клиентский API выступает коннектором веб-чата: публикует во входящий поток, а не пишет в БД напрямую — единый путь
  для всех каналов (Ф4 добавит Telegram и email по тому же контракту).
- Порядок показа сообщений — по времени приёма системой (`sent_at`), синхронизация — по нему же: при параллельной
  обработке двумя экземплярами worker порядок не нарушается.
- `text/plain` принимается как байты (не строка): иначе загрузка текстовых файлов ломалась (найдено e2e-тестом).
- Результаты «Передать на 2-ю линию» и «Отложено / перезвонить» пока отклоняются с пояснением: передача — Ф8,
  отложенные обращения с напоминанием — Ф3 (нужны таймеры pg-boss).

**Известные ограничения**

- Распределение — ручное («Взять»); автоматическое — Ф3. Ограничение частоты сообщений — в памяти экземпляра.
- Антивирусная проверка вложений — позже (FS-SEC-03); опасные расширения отклоняются.

  - сотрудники: роли, области, шаблоны областей, очереди, навыки, сброс пароля, разблокировка, отключение;
  - матрица: список с фильтрами, массовое назначение (только сотрудники 2-й линии с входом и email), снятие,
    копирование между предприятиями, отчёт «без ответственного», **подстановка ответственных, кураторов и срока по
    умолчанию** (`org/matrix.ts`: подтема → тема → корень отдельно для каждого вида; срок — ближайший по дереву,

  - настройки (срок по умолчанию, время рассылки, режим согласования), журнал аудита.
- `bootstrap` (сервис `migrate` в compose): миграции, первый администратор, демо-данные (`SEED_DEMO=true`).
- Веб-приложение `apps/web` (React 19, Mantine 8, TanStack Query): вход, меню по правам, предприятия, подразделения,

**Решения и находки**

- **Маршруты Traefik перенесены из меток контейнеров в файл `infra/traefik/dynamic.yml`.** При поэтапном обновлении
  старые и новые контейнеры работают одновременно; если метки маршрутов у них различаются, Traefik считает это
  конфликтом и снимает маршрут (получили сотни ответов 404). Теперь метки описывают только сервис (порт, проверку
  готовности), а маршруты и повторы не зависят от версии контейнера.
- Статика (nginx) останавливается так же корректно, как api: `/healthz` → 503, пауза, плавное завершение с лимитом.
- `jose` 5 (поддержка CommonJS), argon2 — `hash-wasm` (без нативных модулей: одинаково на любой платформе и в офлайн-сборке).
- Роль и ответственность разделены: роль — «что умеет», строка матрицы — «за что отвечает» (02-архитектура, 5.1).
- По умолчанию новый сотрудник видит «всё» (В-34); ограничение — областями.

**Известные ограничения**

- 2FA для администраторов, SSO/AD — позже (Ф12 / после MVP).
- Области видимости применяются к справочникам, матрице и связям подразделений; к обращениям и тикетам — в Ф2 и Ф8
  (та же функция `scopeFilter`).
- Демо-пароли (`DEMO_PASSWORD`) — только для стендов.

## Ф0. Каркас, инфраструктура, service-kit — выполнена (27.09.2026)

**Сделано**

- Монорепозиторий `mvp/`: pnpm 10 + Turborepo, TypeScript 5.9 (strict), ESLint 9, Prettier, Vitest 3.
- `packages/contracts` — оболочка события (UUIDv7, версия, тип `domain.entity.action`, аддитивная совместимость).
- `packages/db` — SQL-миграции `NNNN_(expand|contract)_*.sql`, раннер под advisory lock с контрольными суммами,
  таблицы `outbox`, `event` (append-only, защищена триггером), `feature_flag`; схема Drizzle.
- `packages/service-kit` — конфиг (zod), JSON-логи pino с маскированием секретов, `Lifecycle` (корректная
  остановка: readiness 503 → пауза → хуки по порядку → выход, аварийный тайм-аут), подключение к NATS с
  бесконечным переподключением, `ensureStream`, transactional outbox + `OutboxRelay` (SKIP LOCKED, Nats-Msg-Id),
  метрики Prometheus.
- `apps/api` — NestJS 11 + Fastify: `/api/v1/ping`, `/api/v1/demo/events` (демонстрация outbox), `/healthz`,
  `/readyz`, `/metrics`; во время остановки отвечает `Connection: close` и закрывает освободившиеся keep-alive.
- `infra/compose` — Traefik 3.6 (HTTPS, health-check `/readyz` раз в секунду, retry), PostgreSQL 16,
  NATS 2.11 кластер ×3 (JetStream R3), SeaweedFS (S3), одноразовый сервис миграций, api ×2;
  профиль `observability`: Prometheus, Grafana, Loki, Promtail.
- `ops/rollout.sh` — поэтапное обновление; `ops/build-images.sh` — сборка без сети внутри Docker;
  `ops/mirror/*` — офлайн-комплект, импорт, публикация в свой реестр; `ops/licenses/check.mjs`;
  `ops/test/migrations-lint.mjs` (правило expand/contract); тесты `rollout-under-load`, `nats-failover`.
- CI: `.github/workflows/mvp.yml` — формат, lint, build, typecheck, unit-тесты, лицензии, линтер миграций,
  squawk; отдельная задача — поэтапное обновление под нагрузкой и отказ узла NATS в Docker.

**Решения и отступления от плана**

- S3-хранилище — **SeaweedFS** (Apache 2.0) вместо MinIO (В-36): риски смены лицензии/политики сборок MinIO.
- Вместо внешнего плагина docker-rollout — собственный `ops/rollout.sh` (меньше внешних зависимостей).
- **Traefik 3.6+ обязателен** для Docker Engine 29+: Traefik 3.5 обращается к Docker API 1.24 и получает отказ.
- Версии зафиксированы на проверенных линиях (TypeScript 5.9, NestJS 11, zod 3, Vitest 3), а не на только что
  вышедших мажорных (TypeScript 7, NestJS 12) — обновление отдельной задачей.
- Метрики NATS в Prometheus не собираются (нужен prometheus-nats-exporter) — при развитии мониторинга.

**Известные ограничения**

- Сертификат HTTPS — самоподписанный сертификат Traefik; для сервера — свой сертификат или ACME.
- Задача CI `zero-downtime` скачивает образы из Docker Hub; при его лимитах — использовать зеркало/свой реестр.
- Kamailio/Asterisk/coturn — в Ф5; остальные сервисы (realtime, router, worker, коннекторы) — в своих фазах.

**Как проверить** — см. `README.md`, разделы «Быстрый старт» и «Обновление без остановки».
