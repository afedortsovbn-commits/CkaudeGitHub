# Руководство по развёртыванию

Для кого: администратор сервера заказчика. Результат: контакт-центр работает на своём сервере в закрытом контуре,
без обращения к публичным облакам (M-NFR-01, M-NFR-10). Время: ≈ 1 час на подготовленном сервере.

Связанные документы: [руководство администратора](руководство-администратора.md) (настройка системы после
установки), [регламент обновления](регламент-обновления.md) (выпуск новых версий без остановки),
[`README.md`](../README.md) (состав и команды для разработчиков).

## 1. Сервер

| Параметр       | Демонстрация MVP (10 операторов, 30 вызовов, 100 чатов)                                                   |
| -------------- | --------------------------------------------------------------------------------------------------------- |
| Процессор, ОЗУ | 8 vCPU, 16 ГБ (проверено на 4 vCPU — под полной нагрузкой автотеста на пределе)                           |
| Диск           | SSD 100 ГБ: БД, записи разговоров (≈ 1 МБ/мин, срок хранения — в «Настройках»), резервные копии           |
| ОС             | Linux x86-64 (Ubuntu 24.04, AlmaLinux 9 и др.) с Docker Engine 29+ и Docker Compose v2                    |
| Сеть           | Статический адрес; для удалённых операторов — внешний адрес или NAT с пробросом портов (см. таблицу ниже) |

Порты сервера:

| Порт               | Назначение                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------------ |
| 443/tcp (80 → 443) | Веб-интерфейс, API, WebSocket, виджет чата (Traefik, TLS)                                              |
| 8443/tcp           | WSS софтфона операторов (Kamailio, в обход Traefik)                                                    |
| 5060/udp           | SIP-транк оператора связи (только с адреса транка)                                                     |
| 3478, 3479/udp,tcp | TURN (coturn ×2) — медиа для операторов за NAT                                                         |
| 10000–10399/udp    | RTP узлов Asterisk (узел 1 — 10000–10199, узел 2 — 10200–10399; наружу — при `MEDIA_EXTERNAL_ADDRESS`) |

Наружу из контура нужен только доступ к `api.telegram.org` (или локальному Bot API) — для Telegram-ботов, к SMTP/IMAP
заказчика — для почты, и к API Rocket Data — после Ф13. Всё остальное работает без интернета.

## 2. Комплект поставки

На машине с интернетом (или из собственного зеркала):

```bash
cd mvp
ops/build-images.sh v1                 # образы cc/*:v1 (код собирается на хосте; внутри Docker ничего не качается)
ops/mirror/export.sh offline-bundle    # все Docker-образы + все npm-пакеты по lockfile
```

Перенести на сервер каталог репозитория и `offline-bundle/`, затем:

```bash
ops/mirror/import.sh offline-bundle    # загрузить образы в Docker сервера
# при необходимости пересобрать без интернета:
PNPM_STORE=offline-bundle/pnpm-store PNPM_OFFLINE=1 ops/build-images.sh v1
```

Если Docker Hub недоступен, а нужные базовые образы есть в другом зеркале — задайте переменные `*_IMAGE`
(`POSTGRES_IMAGE`, `TRAEFIK_IMAGE`, `NATS_IMAGE`, `S3_IMAGE`, `COTURN_IMAGE`) и при сборке — `NODE_IMAGE`,
`NGINX_IMAGE`, `ASTERISK_IMAGE`, `KAMAILIO_RPMS_IMAGE`, `BASE_IMAGE`.

## 3. Настройка: `infra/compose/.env`

Создайте файл `mvp/infra/compose/.env` (права `600`). Обязательно — свои значения секретов:

```ini
API_TAG=v1                      # версия образов (release.sh обновляет сам)
MEDIA_TAG=v1
JWT_SECRET=<случайная строка ≥ 32 символов>
SECRETS_KEY=<случайная строка ≥ 16 символов>   # шифрует токены ботов, пароли почты, секреты 2FA в БД
POSTGRES_PASSWORD=<пароль БД>
BOOTSTRAP_ADMIN_EMAIL=admin@example.by
BOOTSTRAP_ADMIN_PASSWORD=<временный пароль первого администратора>
SIP_SECRET=<…>  ARI_PASSWORD=<…>  TURN_SECRET=<…>
PUBLIC_BASE_URL=https://cc.example.by           # внешний адрес: ссылки в письмах, OpenAPI, webhook Telegram
SIP_DOMAIN=cc.example.by
```

Сгенерировать секреты: `openssl rand -base64 36`. **Храните `.env` как секрет и включайте в резервную копию**
(ops/backup.sh копирует его): без `SECRETS_KEY` не расшифровать токены каналов и секреты 2FA.

По необходимости:

| Переменная                                                            | Когда нужна                                                                                                                                                                                                                                      |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `TRUNKS`                                                              | SIP-транки для исходящих с приоритетом и резервом: `хост:порт;приоритет` через запятую, 1 — основной (например, `mts-1.by:5060;1,mts-2.by:5060;2`). При отказе транка (5xx), отсутствии ответа или неразрешаемом адресе вызов уходит в следующий |
| `TRUNK_HOST`                                                          | Один SIP-транк (`host:port`) — если `TRUNKS` не задан (совместимость)                                                                                                                                                                            |
| `TRUNK_ALLOW`                                                         | Адреса/сети транка, с которых Kamailio принимает вызовы (`a.b.c.d, e.f.g.0/24`); пусто — любые. Если задан, к нему добавляются адреса всех транков из `TRUNKS`. На сервере задать обязательно (плюс межсетевой экран на 5060/udp)                |
| `MEDIA_EXTERNAL_ADDRESS`, `TURN_URLS`                                 | Операторы вне локальной сети (за NAT): внешний адрес медиа и адреса TURN                                                                                                                                                                         |
| `TICKET_SMTP_HOST`, `_PORT`, `_SECURE`, `_USER`, `_PASSWORD`, `_FROM` | Письма 2-й линии («Важно!», ежедневная рассылка)                                                                                                                                                                                                 |
| `API_REPLICAS`, `WORKER_REPLICAS`, … (`*_REPLICAS`)                   | Число экземпляров сервисов (по умолчанию 2 — нужно для обновления без простоя)                                                                                                                                                                   |
| `LOG_LEVEL`                                                           | `info` (по умолчанию), `debug` — для разбора проблем                                                                                                                                                                                             |

## 4. Сертификаты

- **Веб (443)**: положите сертификат домена (с цепочкой) и ключ в `mvp/infra/traefik/certs/cert.pem` и `key.pem`
  (в git не попадают), в `.env` задайте `TRAEFIK_TLS=../traefik/tls-certs.yml` и выполните
  `docker compose -f infra/compose/docker-compose.yml up -d traefik`. Продлённый сертификат (замена файлов)
  подхватывается без перезапуска. Без этого — самоподписанный сертификат Traefik (браузер предупредит). Минимальная
  версия — TLS 1.2.
- **Софтфон (8443, WSS Kamailio)**: тот же сертификат в томе `sipcerts` (`cert.pem`, `key.pem`):
  `docker run --rm -v cc_sipcerts:/t -v $PWD/infra/traefik/certs:/s alpine cp /s/cert.pem /s/key.pem /t/`, затем
  `ops/update-media.sh kamailio`. С самоподписанным сертификатом каждый оператор один раз открывает
  `https://<адрес>:8443` и принимает сертификат.

## 5. Первый запуск

```bash
cd mvp
docker compose -f infra/compose/docker-compose.yml up -d --wait
```

Сервис `migrate` применяет миграции БД и создаёт первого администратора (`BOOTSTRAP_ADMIN_*`); остальные сервисы
стартуют после него. `--wait` завершается, когда все проверки здоровья зелёные (≈ 2–3 мин при первом запуске).

Демо-стенд с тестовыми данными и заглушками внешних систем — см. [сценарий демонстрации](сценарий-демонстрации.md)
(`ops/demo.sh`). **На рабочем сервере `SEED_DEMO` не включать.**

## 6. Проверка установки

```bash
docker compose -f infra/compose/docker-compose.yml ps          # все сервисы healthy, migrate — exited (0)
curl -sk https://localhost/api/v1/ping                           # {"ok":true,…}
curl -sk https://localhost/version.json                          # версия интерфейса
```

1. Войти `https://<адрес>` под `BOOTSTRAP_ADMIN_EMAIL`, сменить пароль («Профиль» — щелчок по своему имени в
   шапке), включить **вход с кодом (2FA)**, в «Настройках» — «2FA обязательна для администраторов».
2. Выполнить первичную настройку по [руководству администратора](руководство-администратора.md), раздел 2.
3. Позвонить на номер канала (или с `/demo-call` на стенде) и написать в виджет — обращения видны оператору.
4. Сделать первую резервную копию и проверить её: `ops/backup.sh && ops/restore.sh --verify out/backups/<каталог>`.

## 7. Резервное копирование (M-NFR-06)

```bash
ops/backup.sh                                  # БД (pg_dump) + объекты S3 + .env → out/backups/<дата-время>
ops/restore.sh --verify out/backups/<каталог>  # проверка копии: временная БД и бакет, сверка строк и sha256
ops/restore.sh out/backups/<каталог>           # авария: полное восстановление (сервисы останавливаются)
```

Копия снимается на работающей системе (обработка обращений не останавливается). Расписание — cron хоста, например
ежедневно в 02:30 с хранением 14 копий и проверкой:

```cron
30 2 * * * cd /opt/cc/mvp && KEEP=14 ops/backup.sh >> /var/log/cc-backup.log 2>&1 && ops/restore.sh --verify "$(ls -1d out/backups/*/ | tail -1)" >> /var/log/cc-backup.log 2>&1
```

Каталог `out/backups` копируйте на отдельный носитель/сервер. Потеря данных при аварии — с момента последней копии
(PITR и кластер PostgreSQL — после MVP). Восстановление: секреты `.env` должны совпадать с копией (файл `env` в
каталоге копии).

## 8. Обновление

Только командами компонентов, не общим `docker compose up` — см. [регламент обновления](регламент-обновления.md):
`ops/release.sh <тег>` (прикладные сервисы по одному экземпляру, без простоя), `ops/update-media.sh` (Asterisk,
coturn, NATS, Kamailio).

## 9. Наблюдаемость

`docker compose -f infra/compose/docker-compose.yml --profile observability up -d` — Prometheus (`:9090`), Loki и
Grafana (`:3001`, пароль `GRAFANA_PASSWORD`). Логи сервисов — JSON с `correlation-id`, телефоны, email и тексты
клиентов в логах маскируются (M-NFR-07); `LOG_PII=1` у сервиса отключает маскирование (только для отладки на
тестовом стенде).

## 10. Частые проблемы

| Признак                                                     | Причина и решение                                                                                                |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Traefik не видит контейнеры, 404 на всё                     | Docker Engine 29+ требует Traefik ≥ 3.6 (используется по умолчанию); не подменять `TRAEFIK_IMAGE` старой версией |
| `docker pull` упирается в лимит Docker Hub                  | Взять образы из зеркала (`mirror.gcr.io/library/<образ>`) и переименовать `docker tag`, либо задать `*_IMAGE`    |
| Софтфон «Телефон не подключён»                              | Открыть `https://<адрес>:8443` и принять сертификат; проверить, что 8443/tcp открыт                              |
| Нет звука у удалённого оператора                            | Задать `MEDIA_EXTERNAL_ADDRESS` и `TURN_URLS`, открыть порты TURN и RTP                                          |
| Сервис после `stop`/`start` не становится healthy           | Посмотреть `docker compose logs <сервис>`; перезапуск по одному — `ops/rollout.sh <сервис>`                      |
| Письма 2-й линии не уходят                                  | Проверить `TICKET_SMTP_*`; очередь писем — таблица `notification`, повторы идут сами                             |
| Неподдерживаемый браузер (предупреждение на странице входа) | Google Chrome, Яндекс Браузер или Microsoft Edge последних версий (M-NFR-02)                                     |
