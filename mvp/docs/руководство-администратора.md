# Руководство администратора

Для кого: администратор контакт-центра (роль «Администратор»). Все настройки делаются в веб-интерфейсе и
**применяются без перезапуска** (M-ADM-04). Каждое изменение пишется в «Журнал аудита» (было → стало, кто, когда).

Установка сервера — [руководство по развёртыванию](руководство-развёртывания.md); работа оператора —
[руководство оператора](руководство-оператора.md).

## 1. Роли, права и области видимости

| Роль                                | Что может                                                                                                                                            |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Администратор                       | Всё: администрирование, отчёты, согласования; видит все обращения (право «всё»)                                                                      |
| Супервизор                          | Панель реального времени, прослушивание, суфлирование, вмешательство, перехват, подсказки в чате, отчёты, согласования 2-й линии, объявления о сбоях |
| Оператор                            | Рабочее место: звонки, чаты, карточка, передача на 2-ю линию, согласование своих тикетов                                                             |
| Ответственный / куратор (2-я линия) | Кабинет 2-й линии: свои тикеты, закрытие с ответом, переадресация                                                                                    |

**Области видимости** («Сотрудники» → сотрудник → «Области видимости») ограничивают, какие обращения, тикеты и
данные отчётов видит сотрудник: правило = предприятия × подразделения × темы (пустое поле — «все», тема включает
подтемы); правил может быть несколько (ИЛИ). Чужое обращение не видно ни в списках, ни в поиске, ни в отчётах, по
прямой ссылке — «не найдено». Правила можно сохранить шаблоном и применять к другим сотрудникам.

**Неклассифицированные обращения** (без предприятия и темы — новые, ещё не разобранные) сотрудник с ограниченной
областью по умолчанию **не видит** (В-52). Включить:

- для всех сотрудников роли — «Сотрудники» → любой сотрудник → «Роли» → переключатель «Роли видят
  неклассифицированные обращения»;
- для одного сотрудника — «Области видимости» → «Неклассифицированные обращения»: «как в ролях / видит / не видит»
  (отметка сотрудника важнее роли).

Действует во всех списках, поиске, карточке, уведомлениях в реальном времени, на панели супервизора и в отчётах.

**Слияние дублей клиентов** (право `contacts.merge` — у ролей «Администратор» и «Супервизор»): в карточке клиента
«Объединить с…» → поиск второго клиента → выбор основного → «Объединить». Идентификаторы в каналах, обращения,
согласия и вложения дубля переходят к основному, пустые поля основного дополняются; дубль больше не находится в
поиске. Открытый у клиента чат продолжает работать. Необратимо; кто и когда объединил — в журнале аудита
(`contact.merge`).

**Супервизор в разговоре и в чате** (Ф14): права `calls.whisper` (суфлирование), `calls.barge` (вмешательство),
`conversations.takeover` (перехват звонка или чата), `conversations.hint` (подсказка оператору в чате) — у ролей
«Супервизор» и «Администратор». Подключение к звонку и перехват возможны только для обращений в области видимости
супервизора; каждое подключение, смена режима и перехват — в журнале аудита (`call.listen`, `call.whisper`,
`call.barge`, `call.takeover`, `conversation.takeover`) и в журнале вызова.

## 2. Первичная настройка (рекомендуемый порядок)

1. **«Настройки»**: срок ответа 2-й линии по умолчанию, время ежедневной рассылки, режим согласования, пороги
   панели супервизора, параметры SL (раздел 4), безопасность и ПДн (разделы 5–6).
2. **«Предприятия»**, **«Подразделения»** — подразделение добавляется в одно или несколько предприятий.
3. **«Темы и поля»** — дерево тем/подтем, особо важные темы (обращение помечается автоматически), срок ответа
   2-й линии для темы, поля карточки (обязательные при закрытии / при передаче).
4. **«Объекты»** — справочник АЗС с привязкой к предприятию (импорт из CSV) и GUID объекта АСУ НПО ЭК (по нему
   сопоставляются отзывы Rocket Data). **«Синхронизация объектов»** — ежедневная загрузка справочника АЗС из АСУ НПО
   ЭК (формат «АСУ НПО ЭК»: адрес выгрузки, время, предельная доля деактивации, **предприятие объектов выгрузки** —
   по умолчанию «ПОН» — и исключения по коду предприятия выгрузки); «Проверить (без изменений)» показывает, что
   изменится; журнал запусков с перечнем изменений. Синхронизируемые объекты вручную не правятся. Перед первым запуском
   заведите в «Предприятиях» ПОН, Управление цифровизации, Управление «Маланка», Центральный аппарат, Мингорисполком
   (формат выгрузки и правила — [интеграции-rocketdata-и-объекты.md](интеграции-rocketdata-и-объекты.md)).
5. **«Справочники»** — результаты обработки, способы ответа 2-й линии, причины перерыва, навыки, очереди
   (каналы, приоритет, стратегия, перелив, максимальное ожидание, постобработка, **«Обязательный тег при
   закрытии»** — обращение очереди нельзя закрыть или передать на 2-ю линию без тега), расписания, правила
   маршрутизации текста. В «Настройках» — через сколько секунд молчания клиента после ответа оператора чат попадает
   во вкладку оператора «Постобработка» (по умолчанию 300). **«Сообщать позицию в очереди»** (опция очереди, по
   умолчанию выключена, Ф14): звонящему при постановке в очередь и затем раз в «Повторять позицию каждые, с» звучит
   «Вы второй в очереди» (позиция — в порядке распределения: приоритет, затем время ожидания; звонки считаются
   отдельно от чатов); в автоответе «в очереди» текстовых каналов доступна переменная `{{позиция}}`. Фраза собирается
   из фрагментов «Аудиобиблиотека» → «Позиция в очереди» («Вы», «в очереди», порядковые «первый»…«девятнадцатый» и
   десятки «двадцатый»…«девяностый»); если какого-то фрагмента нет, позиция не звучит (в журнале вызова — отметка).
   Позиции больше 99 не озвучиваются. Включение и выключение действуют сразу.
6. **«Сотрудники»** — роли, области видимости, очереди, навыки, основное предприятие/подразделение. Email обязателен
   ответственным и кураторам (письма 2-й линии).
7. **«Матрица ответственности»** — ответственные и кураторы по подразделению на предприятии × теме.
8. **«Каналы»** — голосовой (номера DID), веб-чат и чат в приложении (текст и версия согласия на обработку ПДн,
   разрешённые сайты), Telegram-боты, почтовые ящики, внешний канал по API, **отзывы с карт (Rocket Data)** — адрес
   приёма отзывов (колонка «Адрес», `https://<адрес КЦ>/rd/<id канала>`) передаётся Rocket Data, в настройках канала —
   адрес сервиса ответов Rocket Data (пусто — ответы не отправляются; **на тестовом стенде не указывайте адрес рабочей
   Rocket Data**); для канала отзывов — своя очередь.
   Канал начинает работать сразу; состояние подключения и журнал обмена — там же. Ответ на отзыв публикуется на
   площадке, поэтому автоответы на отзывы уходят только по правилам, где канал «Отзыв» выбран явно.
   **«Анкета перед чатом»** (веб-чат и чат в приложении): для имени, телефона и email — «Не спрашивать»,
   «Необязательно» или «Обязательно». Пока обязательные поля не заполнены, кнопка «Начать чат» недоступна и виджет
   подсказывает, что заполнить; телефон проверяется на формат (номер, по которому можно перезвонить) и сохраняется в
   карточке клиента в виде +375…. По умолчанию — имя и телефон, оба необязательные.
9. **«Сценарии IVR»**, **«Аудиобиблиотека»**, **«Объявления о сбоях»** — голосовое меню без программирования,
   публикация новой версии не затрагивает идущие звонки, откат — «Версии».
   **«Все операторы заняты»**: в шаге «Поставить в очередь» — поле «Фраза „Все операторы заняты“». Она звучит один
   раз при постановке в очередь, если свободных операторов нет (все разговаривают, на перерыве или не в сети), затем —
   музыка и периодическое сообщение. Пусто — сразу музыка, как раньше.
10. **«Боты»**, **«Автоответы»**, **«Шаблоны ответов»**, **«База знаний»**, **«Подсказки: провайдеры»**. У шагов бота,
    ждущих ответа клиента («Меню кнопками», «Сбор поля»), — **«Ждать ответа, с»** (Ф14): клиент молчит столько —
    бот напоминает («Напомнить, раз», «Текст напоминания»; пусто — повторяет вопрос), затем уходит по выходу
    **«нет ответа»** (не подключён — диалог передаётся оператору; проверка сценария предупреждает об этом). Пусто —
    бот ждёт без ограничения, как раньше. Пока бот ждёт с тайм-аутом, правило автозакрытия этот диалог не трогает. В
    тестовом прогоне — кнопка «Клиент молчит».
    **Навигация по меню бота**: в шаге «Меню кнопками» — переключатели «Кнопка „Назад“» и «Кнопка „В главное
    меню“» (подписи можно изменить). Кнопки появляются сами только во вложенных меню: «Назад» — в предыдущее меню,
    «В главное меню» — в первое меню диалога; связи для них рисовать не нужно. Клиент может нажать кнопку или
    написать её текст или номер.
    **«Автоответы» → вид «Все операторы заняты»**: этот текст уходит клиенту чата вместо «Вы в очереди», если в
    очереди обращения нет ни одного свободного оператора. Нет такого правила — как раньше, «Вы в очереди».
11. **«Интеграции»**, **«Ключи API»**, **«Webhooks»**, **«Внешний бот»** — связи с внешними системами (описание —
    «Документация API»).

Готовую конфигурацию можно перенести с тестового стенда: **«Экспорт и импорт»** (без секретов; импорт сначала
показывает отчёт проверки).

## 3. Сотрудники: блокировка, увольнение, обезличивание

- **Пароль** — «Доступ» → «Задать пароль» (сессии сотрудника завершаются). Пароли хранятся как argon2id; после 5
  неудачных попыток вход блокируется на 15 минут («Снять блокировку входа» — там же).
- **Вход с кодом (2FA)** — сотрудник включает сам в «Профиле» (щелчок по своему имени в шапке). Для
  администраторов её можно сделать обязательной: «Настройки» → «Вход с кодом (2FA) обязателен для администраторов» —
  при следующем входе администратор отсканирует QR-код приложением-аутентификатором (FreeOTP, Яндекс Ключ, Google
  Authenticator; работают без интернета). Потерян телефон — «Доступ» → «Сбросить (потерян телефон)».
- **Увольнение** — «Доступ» → «Отключить (уволить)»: вход невозможен, сессии завершены; открытые тикеты уволенного
  попадают в «Контроль 2-й линии» → «Требуют переназначения», его ответы на согласование — супервизорам.
- **Обезличивание уволенного** (по заявлению или сроку) — у отключённого сотрудника «Обезличить (ФИО, email,
  телефон)», указать основание. ФИО заменяется на «Сотрудник удалён (…)», контакты и пароль стираются; история
  обращений и отчёты сохраняются. Необратимо.

## 4. Параметры расчёта SL (В-51)

«Настройки» → «Панель супервизора и отчёты». Действуют сразу — в отчёте «SL и пропущенные» и на панели
супервизора («SL за сегодня»).

| Параметр                                                    | По умолчанию | Смысл                                                                 |
| ----------------------------------------------------------- | ------------ | --------------------------------------------------------------------- |
| SL: ответ на звонок / в текстовом канале в пределах, с      | 20 / 60      | Общий порог ответа                                                    |
| Порог SL по очереди (таблица: голос, текст)                 | пусто        | Свой порог очереди; пусто — общий                                     |
| Короткий сброс, с                                           | 5            | Клиент ушёл быстрее — не пропущенный                                  |
| SL: учитывать короткие сбросы как пропущенные               | выкл.        | Вкл. — короткие сбросы входят в знаменатель и в долю пропущенных      |
| SL: учитывать возвраты из очереди в IVR/бот в знаменателе   | выкл.        | Вкл. — такой эпизод считается не отвеченным в пределах SL             |
| SL: постановка в очередь после перевода — новое поступление | вкл.         | Выкл. — в расчёт входит только первое поступление обращения в очередь |

SL = отвечено в пределах порога ÷ (отвечено + пропущено [+ короткие сбросы] [+ возвраты в IVR/бот]). Пояснения под
таблицей отчёта всегда показывают действующие правила.

## 5. Безопасность

- TLS снаружи (Traefik) и для WebRTC (WSS, DTLS-SRTP); права проверяются на сервере при каждом запросе.
- **«Журнал аудита»** — неизменяемый: административные действия (было → стало), входы и неудачные попытки,
  прослушивание записей, выгрузки отчётов, обезличивание. Фильтр по объекту (`app_user`, `topic`, `contact` …).
- Ключи API показываются один раз, отзыв действует за секунды; секреты каналов и интеграций хранятся в БД
  зашифрованными (`SECRETS_KEY`).

## 6. Персональные данные (M-NFR-07)

Раздел **«Персональные данные»**:

- **Реестр согласий** — кто, когда, в каком канале и с какой **версией текста** согласился (поиск по имени,
  телефону, email). Факт согласия виден и оператору в карточке клиента.
- **Тексты согласий** — все версии текста по каналам. Текст задаётся в «Каналах» (веб-чат, чат в приложении);
  изменить его можно **только с новой версией** (прежние хранятся навсегда) — клиенты увидят новый текст и
  согласятся заново.
- **Обезличивание клиента** (по заявлению субъекта ПДн) — найти клиента, указать основание, «Обезличить». Стираются
  имя, телефон, email, идентификаторы в каналах (при новом обращении это будет новый клиент), тексты его сообщений
  и вложения, записи разговоров, поля карточек, IP в согласиях — в том числе в журнале событий и доставках
  webhooks. Обращения (канал, тема, результат, время) остаются для отчётов. Сначала закройте открытые обращения
  клиента. Необратимо, основание — в журнале аудита.

**Срок хранения записей разговоров** — «Настройки» → «Срок хранения записей разговоров, дней» (по умолчанию 180,
В-11). Раз в час файлы старше срока удаляются из хранилища; в карточке остаётся отметка «запись удалена».
Переписка хранится бессрочно.

В журналах сервисов телефоны, email, имена и тексты клиентов маскируются автоматически.

## 7. Резервные копии, обновления, контроль

- Резервное копирование и проверка копии — [руководство по развёртыванию](руководство-развёртывания.md), раздел 7.
- Обновление без остановки — [регламент обновления](регламент-обновления.md); «Настройки» → фиче-флаги и журнал
  выпусков.
- «Супервизор» и «Отчёты» — контроль работы; пороги подсветки — в «Настройках».
