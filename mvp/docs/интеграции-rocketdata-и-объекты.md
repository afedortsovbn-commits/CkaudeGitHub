## 1. Rocket Data — контракт-заглушка

Авторизация — `Authorization: Bearer <токен>` (токен — в настройках канала «Отзыв», хранится зашифрованным). Адрес API
— настройка канала; из закрытого контура — через прокси (`ROCKETDATA_PROXY` в `infra/compose/.env`, передаётся
коннектору как `HTTPS_PROXY` с `NODE_USE_ENV_PROXY=1`). Все запросы — с таймаутом 20 с.

### 1.1 Отзывы: `GET {api_url}/v1/reviews?updated_since=<ISO 8601>&cursor=<курсор>&limit=100`

Отзывы, созданные или изменённые начиная с `updated_since`, по возрастанию `updated_at`; постранично.

```json
{
  "items": [
    {
      "id": "rv-123",
      "location_id": "rd-azs-1",
      "location_code": "AZS-1",
      "platform": "yandex",
      "rating": 2,
      "text": "Долго ждал на кассе",
      "author_name": "Иван",
      "published_at": "2026-09-29T10:00:00Z",
      "updated_at": "2026-09-29T10:00:00Z",
      "url": "https://yandex.by/maps/org/…/reviews",
      "answer": { "text": "Спасибо!", "status": "published", "published_at": "…" }
    }
  ],
  "next_cursor": "…"
}
```

- `id`, `updated_at` — обязательны; `platform` — `google`, `yandex`, `2gis` (другие показываются как есть); `rating`
  1–5 или `null`; `answer` — ответ на площадке (из системы или вне её), `null` — нет.
- Некорректная запись пропускается (запись в журнале канала), остальные загружаются.

### 1.2 Ответ на отзыв: `POST {api_url}/v1/reviews/{id}/answer`

Тело `{"text": "…"}`, заголовок `Idempotency-Key: <id сообщения в системе>` — повтор запроса с тем же ключом не создаёт
второй ответ. Ответ: `{"id": "…", "status": "published" | "pending" | "rejected", "error": "…"}`.

| Ответ Rocket Data                         | Статус сообщения у оператора                              |
| ----------------------------------------- | --------------------------------------------------------- |
| 2xx, `published` или `pending`            | ✓ отправлено                                              |
| 2xx, `rejected`                           | ⚠ не доставлено: площадка отклонила ответ (без повторов) |
| 4xx (кроме 408/429): отзыв удалён, запрет | ⚠ не доставлено (без повторов)                           |
| 408, 429, 5xx, сеть                       | повторы с паузой до `OUTBOUND_MAX_ATTEMPTS`, затем ⚠     |

Файлы площадки не принимают: ответ с вложением сразу получает «не доставлено».

### 1.3 Как отзыв становится обращением

- Каждое подключение к Rocket Data — канал «Отзыв» («Администрирование → Каналы»): адрес API, токен, период опроса
  (по умолчанию 300 с), глубина первой загрузки (7 дней), «срочные — с оценкой не выше» (2), «не создавать обращения по
  отзывам, на которые уже ответили на площадке» (включено). Очередь канала — очередь отзывов.
- Опрос ведёт один из двух экземпляров `connector-rocketdata` (аренда в NATS KV); отметка «изменены начиная с» — в
  NATS KV `cc_rd_state` (с запасом 5 минут назад). Отзыв → `CC_INBOUND` → worker.
- **Ключ идемпотентности** — id отзыва + отпечаток оценки и текста: повторная загрузка не создаёт дублей; изменённый
  автором отзыв — новое сообщение того же открытого обращения (если обращение закрыто — новое обращение).
- **Клиент** обращения — автор отзыва (у площадок нет устойчивого идентификатора автора — каждый отзыв свой клиент).
- **Объект и предприятие**: точка Rocket Data сопоставляется объекту справочника по `external_ids.rocketdata`
  (= `location_id`), иначе по коду объекта (= `location_code`). Не найдено — обращение без предприятия (права: видят
  те, кому разрешены неклассифицированные) и служебная подсказка оператору.
- Автоответы, приветствия, автозакрытие по молчанию и сообщение о передаче на 2-ю линию **на отзывы не отправляются**
  (ответ публичный), кроме правил автоответов, где канал «Отзыв» выбран явно.

## 2. Справочник объектов — контракт-заглушка

«Администрирование → Синхронизация объектов» (право `admin.directories`): адрес выгрузки (HTTP GET), формат (JSON или
CSV), токен (`Authorization: Bearer`, хранится зашифрованным), время ежедневного запуска (Europe/Minsk), предельная доля
деактивации. Плановый запуск выполняет worker (pg-boss раз в минуту проверяет время; после ошибки — повтор не чаще
раза в час до конца суток). Там же — «Проверить (без изменений)», «Синхронизировать сейчас» и журнал запусков.

**JSON** — массив объектов или `{"items": [...]}`:

```json
[
  {
    "code": "AZS-1",
    "name": "АЗС №1",
    "address": "г. Минск, …",
    "enterprise_code": "E1",
    "external_ids": { "rocketdata": "rd-azs-1" },
    "is_active": true
  }
]
```

Принимаются и `enterpriseCode`, `externalIds`, `isActive`. **CSV** — колонки ручного импорта `code;name;address;
enterprise_code`, а также `rocketdata`, `ext_<ключ>` (внешние идентификаторы) и `is_active` (`0`, `false`, `нет` —
закрыт); разделитель `;`, `,` или табуляция.

**Правила сверки** (по коду объекта, одной транзакцией):

- нет в справочнике — добавляется (`source = sync`); есть — обновляются название, адрес, предприятие, внешние
  идентификаторы (ключи из выгрузки перекрывают, прочие сохраняются); объект, заведённый вручную или импортом, с тем же
  кодом переходит под синхронизацию;
- `is_active: false` или объекта нет в выгрузке — деактивируется (только синхронизируемые; заведённые вручную не
  трогаются); вернулся — снова активен;
- строка с ошибкой (нет кода/названия, неизвестное предприятие, повтор кода) пропускается и попадает в «замечания»;
  такой объект не деактивируется;
- **защита от ошибочной выгрузки**: пустая выгрузка или деактивация большей доли синхронизируемых объектов, чем
  задано (по умолчанию 30 %), — запуск с ошибкой, справочник не меняется;
- синхронизируемые поля вручную не правятся (карточка объекта, активность, импорт CSV) — ответ 400 с пояснением.
