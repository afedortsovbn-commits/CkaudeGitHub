# Свод требований к КЦ (из «Требования к контакт-центру сокращенно.docx»)

Источник: ТЗ на КЦ для сети 570 АЗС и 1000 ЭЗС (РБ). Приоритеты предварительные, для MVP собственного продукта:
**[MVP]** обязательно в MVP · **[MVP-упрощ.]** в MVP в упрощённом виде · **[Позже]** после MVP.
Пометки «[прим.]» — комментарии составителя, не требования источника.

Контекст (для справки, не требования): 24/7/365; ~15 000 вход. + 5 000 исход. звонков/мес, ~1 000 текстовых обращений/мес; AHT 2,5 мин; B2C и B2B. Тематики 1-го уровня (10): банковские карты, топливо, мобильное приложение, жалобы на персонал АЗС, сайт, подарочные сертификаты, бонусная программа, ЭЗС, топливные карты B2B, сопутствующие товары/питание; подтемы 2–3 уровня задаются при внедрении. Операторы не управляют оборудованием АЗС/ЭЗС — только информационная поддержка.

## 1. Каналы (CH)
- REQ-CH-01 Единая очередь и единая история обращений независимо от канала. [MVP]
- REQ-CH-02 Голосовые вызовы входящие и исходящие (городские и мобильные номера операторов РБ). [MVP]
- REQ-CH-03 Мессенджеры через API (Telegram, Viber, WhatsApp — по выбору заказчика). [MVP-упрощ.] [прим.] в MVP 1 мессенджер (напр. Telegram), остальные — адаптерами позже.
- REQ-CH-04 Чат/чат-бот на сайте и в мобильном приложении, подключение по API. [MVP]
- REQ-CH-05 Исходящие звонки и сообщения через те же каналы; исходящий чат — только с согласия клиента (напр. информирование об акциях). [MVP-упрощ.] [прим.] исходящий звонок — MVP; исходящие рассылки в мессенджеры — позже.
- [прим.] Email и WebRTC в источнике не упомянуты — это требования заказчика из постановки MVP.

## 2. Телефония и IVR (TEL)
- REQ-TEL-01 SIP (RFC 3261); SIP-транки ко всем операторам связи РБ. [MVP]
- REQ-TEL-02 Кодеки G.711, G.729, Opus (Opus предпочтителен). [MVP-упрощ.] [прим.] G.711 + Opus; G.729 — по необходимости.
- REQ-TEL-03 Резервирование: два независимых SIP-транка разных операторов (основной/резервный). [MVP-упрощ.] [прим.] поддержка нескольких транков с failover на уровне конфигурации.
- REQ-TEL-04 Подключение SIM через GSM-шлюзы или виртуальные SIM (SIM-банк). [Позже] [прим.] решается внешним шлюзом, который отдаёт SIP.
- REQ-TEL-05 Настраиваемое приветствие, меняется менеджером без программирования; вариативность по теме/подтеме (напр. при массовых сбоях). [MVP]
- REQ-TEL-06 Быстрое добавление информационных сообщений о сбоях для включения в приветствие. [MVP-упрощ.]
- REQ-TEL-07 Многоуровневое IVR-меню, выбор темы DTMF; возврат в предыдущее меню; выход на оператора. [MVP]
- REQ-TEL-08 Голосовой ввод в IVR (опционально). [Позже]
- REQ-TEL-09 Запись текста/сообщения клиента при отсутствии свободных операторов. [MVP-упрощ.] [прим.] голосовое сообщение + тикет; распознавание — позже.
- REQ-TEL-10 Удержание с музыкой. [MVP]
- REQ-TEL-11 Перевод вызова другому оператору: слепой и консультативный. [MVP-упрощ.] [прим.] слепой — MVP, консультативный — желательно.
- REQ-TEL-12 Автосообщение после завершения разговора оператором («Спасибо за обращение»). [MVP]
- REQ-TEL-13 Пост-опрос CSAT по 5-балльной шкале (DTMF или голос), оценка привязывается к обращению. [MVP-упрощ.] [прим.] только DTMF.
- REQ-TEL-14 Не менее 30 одновременных вызовов (пик по расчёту 10–15). [MVP]

## 3. Маршрутизация и очереди (RT)
- REQ-RT-01 Навыки (skills): каждому оператору назначаются темы компетенции; маршрутизация по теме из IVR. [MVP]
- REQ-RT-02 Алгоритмы распределения: Least Recent, Round Robin, с учётом числа вызовов за смену и текущей загрузки. [MVP-упрощ.] [прим.] Least Recent + загрузка; остальное — стратегиями позже.
- REQ-RT-03 Группа приоритетных операторов на тему; при занятости — перелив на другую группу с нужным навыком. [MVP]
- REQ-RT-04 Правила эскалации: нет оператора с навыком → общая очередь или резервная группа. [MVP]
- REQ-RT-05 Приоритет по теме/сегменту (напр. B2B выше) без выделенной очереди. [MVP-упрощ.]

## 4. Рабочее место оператора (UI)
- REQ-UI-01 Веб-интерфейс: всё в одном окне, интуитивный; быстрый доступ к карточке клиента, истории, управлению вызовом/чатом. [MVP]
- REQ-UI-02 Ведение до 5 чатов одновременно. [MVP]
- REQ-UI-03 Динамическое отображение/фильтрация полей и меню по теме/подтеме, выбранной клиентом. [MVP-упрощ.]
- REQ-UI-04 Для каждой темы/подтемы — набор полей: обязательные (только при передаче в другую службу), необязательные; маски ввода. При закрытии оператором достаточно темы, подтемы и телефона. [MVP]
- REQ-UI-05 Кнопки «Сохранить обращение» / «Передать на обработку». [MVP]
- REQ-UI-06 Озвучивание клиенту выбранного оператором текста (TTS) вместо голоса оператора. [Позже]
- REQ-UI-07 Работа через браузер (последняя версия); при необходимости — внешний SIP-софтфон. [MVP] [прим.] в источнике работа в офисе без VPN; заказчик MVP требует удалённую работу через браузер (WebRTC).
- REQ-UI-08 Профессиональные гарнитуры USB или DECT. [MVP] [прим.] через стандартный WebRTC/ОС-аудио; кнопки гарнитуры (HID) — позже.

## 5. Подсказки, автоответы, боты, транскрибация (AI)
- REQ-AI-01 Шаблоны ответов (быстрые ответы) в чатах. [MVP]
- REQ-AI-02 Гибридный чат-бот: жёсткие сценарии + LLM для свободного диалога (on-premise). [MVP-упрощ.] [прим.] в MVP — сценарный бот + точка расширения под LLM.
- REQ-AI-03 База знаний загружается заказчиком, бот отвечает по ней (RAG). [Позже] [прим.] в MVP — только интерфейс расширения.
- REQ-AI-04 Передача диалога от бота оператору. [MVP]
- REQ-AI-05 Транскрибация записи разговора (on-premise) после сохранения обращения. [Позже]
- REQ-AI-06 NLP-извлечение сущностей (номера карт, суммы, даты, адреса) и автозаполнение полей карточки с ручной правкой. [Позже]
- REQ-AI-07 Для каждого обращения: LLM-резюме диалога и полная стенограмма с таймкодами. [Позже]
- REQ-AI-08 Дообучение моделей (LLM, речевая аналитика) на данных заказчика: сбор данных, дообучение, тестирование. [Позже]

## 6. CRM / карточка клиента (CRM)
- REQ-CRM-01 Идентификация клиента по номеру телефона (или иному ID) независимо от канала; АОН. [MVP]
- REQ-CRM-02 При обращении — автоподгрузка истории взаимодействий по всем каналам. [MVP]
- REQ-CRM-03 Показ данных из CRM (B2C — SAP, B2B — собственная) и истории заправок из ERP. [MVP-упрощ.] [прим.] через коннектор-заглушку/точку расширения.
- REQ-CRM-04 История переписки и исходящие обращения автоматически фиксируются в карточке клиента. [MVP]
- REQ-CRM-05 Классификатор тем 3 уровня (тема/подтема/уровень 3), редактируемый. [MVP]

## 7. Передача в обработку / 2-я линия (TKT)

- REQ-QA-03 Тональность в динамике (график настроения клиента и оператора). [Позже]
- REQ-QA-04 Детекция повышения голоса для каждой стороны. [Позже]
- REQ-QA-05 Выявление нецензурной лексики и запретных слов (список настраивается менеджером). [Позже]
- REQ-QA-06 Просмотр размеченного диалога с выделением проблемных мест; визуальные отчёты по дате/теме/оператору/стороне. [Позже]

## 12. Безопасность и роли (SEC)

- REQ-SEC-03 Ролевая модель и аудит доступа к записям разговоров. [MVP-упрощ.] [прим.] роли оператор/менеджер/админ; полный аудит — позже.
- REQ-SEC-04 Соответствие законодательству РБ о персональных данных (хранение в РБ, контроль доступа). [MVP]
